# S3 Static Website Hosting Configuration

## Problem

When accessing routes directly (e.g., `https://yaligoldstein.com/metrics`), S3 returns 403 Forbidden because it's looking for a file at `/metrics`, but Next.js was generating `metrics.html` instead of `metrics/index.html`.

## Solution Applied

We've configured Next.js to use `trailingSlash: true` in `next.config.ts`, which generates routes as directories with `index.html` files (e.g., `/metrics/index.html` instead of `/metrics.html`).

## Solution: Configure S3 Static Website Hosting

You need to configure your S3 bucket for static website hosting with proper error handling.

### Step 1: Enable Static Website Hosting

1. Go to [AWS S3 Console](https://console.aws.amazon.com/s3/)
2. Select your bucket (the one that hosts `yaligoldstein.com`)
3. Go to **Properties** tab
4. Scroll down to **Static website hosting**
5. Click **Edit**

### Step 2: Configure Static Website Hosting

1. **Static website hosting**: Select **Enable**
2. **Hosting type**: Select **Host a static website**
3. **Index document**: Enter `index.html`
4. **Error document**: Enter `404.html` ⚠️ **IMPORTANT**: Use `404.html`, NOT `index.html`!
   - `index.html` is your home page - using it as error document will always show the home page
   - `404.html` is generated by Next.js and handles client-side routing properly
5. Click **Save changes**

**Why `404.html`?**

- Next.js generates `404.html` which contains the Next.js router
- When S3 can't find a route, it serves `404.html`
- The Next.js router in `404.html` reads the URL and renders the correct page
- This allows direct access to routes like `/metrics` to work correctly

**Note**: With `trailingSlash: true` in Next.js config, routes are generated as directories (e.g., `/metrics/index.html`). When you visit `/metrics/` (with trailing slash), S3 will automatically serve `/metrics/index.html`. If you visit `/metrics` (without trailing slash), S3 will serve `404.html`, which will then route to the correct page.

### Step 3: Note the Website Endpoint

After enabling, you'll see a **Bucket website endpoint** URL like:

```
http://your-bucket-name.s3-website-us-west-1.amazonaws.com
```

**Important**: If you're using CloudFront, make sure CloudFront points to this website endpoint (not the S3 bucket endpoint).

### Step 4: Update CloudFront (if applicable)

If you're using CloudFront:

1. Go to [CloudFront Console](https://console.aws.amazon.com/cloudfront/)
2. Select your distribution
3. Go to **Origins** tab
4. Edit your origin
5. Make sure **Origin domain** points to the S3 website endpoint (not the bucket endpoint)
   - ✅ Correct: `your-bucket.s3-website-us-west-1.amazonaws.com`
   - ❌ Wrong: `your-bucket.s3.us-west-1.amazonaws.com`

### Step 5: Test

1. Wait a few minutes for changes to propagate
2. Visit `https://yaligoldstein.com/metrics` directly
3. It should now work!

## Alternative: CloudFront Error Pages (if using CloudFront)

If you're using CloudFront and the above doesn't work:

1. Go to CloudFront Console
2. Select your distribution
3. Go to **Error pages** tab
4. Click **Create custom error response**
5. Configure:
   - **HTTP error code**: `403: Forbidden`
   - **Customize error response**: Yes
   - **Response page path**: `/index.html`
   - **HTTP response code**: `200: OK`
6. Repeat for `404: Not Found`
7. Click **Create**

## Why This Works

- When you visit `/metrics` directly, S3 can't find that file
- Instead of returning 403, it serves `index.html` (the error document)
- `index.html` loads your Next.js app
- Next.js router sees the URL is `/metrics` and renders the correct page
- Client-side routing takes over
